## 二、实验目标

理解用户地址空间、页表和物理页框之间的关系；实现用户态内存映射与解除映射；在系统调用中校验用户传入的地址、长度和访问权限；验证非法访问会受到页表权限保护。

## 四、实现方法

### 4.1 用户地址和参数检查

`sys_mmap` 与 `sys_munmap` 在调用内存管理接口前检查参数：起始地址必须按页对齐，长度必须大于零，并使用 `checked_add` 计算区间结束地址以避免整数溢出。地址范围限制在 Sv39 用户地址空间低半区 `[0, 2^38)`，避免 `VirtAddr::from` 截断非规范地址后意外落到另一个地址。

`mmap` 的权限参数 `prot` 只接受低三位：位 0、1、2 分别表示读、写、执行。内核将这些位转换为 `MapPermission`，并额外设置 `U`，使映射可由用户态访问。长度不要求是页大小的整数倍，`MapArea` 根据结束地址向上取整覆盖最后一页。

### 4.2 映射内存

映射管理逻辑统一放在 `MemorySet`。`map_user_area` 先遍历目标虚拟页，检查页表中是否已有有效映射；只有整段都空闲时才调用 `insert_framed_area`。该接口为映射分配物理页框、建立页表项并记录 `MapArea`。

任务管理器只定位当前任务，再调用当前任务 `memory_set` 的方法。系统调用层负责检查用户参数并将内核操作结果转换为 `0` 或 `-1`。

### 4.3 解除映射

`unmap_framed_area` 分为验证和修改两个阶段。验证阶段逐页确认目标映射有效、具有用户权限，并且对应的物理页框由当前 `MemorySet` 管理。全部验证成功后才调用 `MapArea::unmap_one` 清除页表项并释放页框。

解除映射可能只覆盖一个区域的一部分，因此实现会拆分并保留未解除的左、右区域记录。这样页表状态、物理页框所有权和 `MemorySet.areas` 元数据保持一致。若范围中任意一页无效，函数在修改前返回失败，避免只解除一部分。

### 4.4 地址访问权限

`sys_trace` 和 `sys_get_time` 根据当前任务页表逐页转换用户虚拟地址，并检查映射有效性、`U` 标志及对应的读写权限。`sys_get_time` 先验证完整的 `TimeVal` 输出范围，再逐字节写入，因此结构体跨越页面时也不会假设物理页连续。

## 五、测试与结果

运行 ch4 用户程序：

```bash
make -C os run OFFLINE=1 BASE=2 TEST=4 CHAPTER=4
```

将输出交给本地 ch4 检查器后，结果为 `Test passed: 16/16`。检查包含时间与 trace 的 ch3 基础项，以及 ch4 的 `mmap0`、`mmap3`、`unmap`、`unmap2` 和 `trace1`。只读映射写入、仅写映射读取等测试触发预期的用户态页故障；错误参数和不完整解除范围返回失败；解除后重新映射成功。

## 六、实验收获

1. 用户虚拟地址不能直接当作物理地址使用。内核需要通过当前任务页表找到对应物理页，并检查页表项权限。
2. 区间操作要先完整验证，再修改状态。否则遇到范围中间的无效页时，可能留下只完成一部分的映射或解除映射结果。
3. 页表映射和 `MemorySet` 中的区域、页框记录必须同步更新。部分解除映射时保留左右两侧区域，避免元数据和真实映射不一致。
4. 权限标志不仅影响软件的参数检查，也会写入硬件页表项，由处理器在用户态访问时执行保护。
